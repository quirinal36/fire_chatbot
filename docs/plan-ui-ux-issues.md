## 목표와 관찰 근거

사용자가 설명을 따로 듣지 않아도 도면의 출처와 수치의 상태를 이해하고, 필요한 보완 작업을 거쳐 검토까지 진행할 수 있게 한다.

| 직접 확인한 현상 | 사용자에게 생기는 문제 | 담당 작업 |
|---|---|---|
| 패널을 좁히면 `기본 도면`, `저장`, `치수 읽기`, `AI 검토`가 한 글자씩 줄바꿈됨 | 버튼을 읽기 어렵고 상태 안내가 도구 영역을 밀어냄 | UX-001 |
| 편집 모드에 따라 캔버스 높이가 486px에서 352px로 줄어듦 | 작업 대상의 위치와 크기가 바뀜 | UX-001 |
| 실제 길이 미설정 상태에서 `87.7㎡`가 강조되고 벽 두께 가정은 작은 글씨로 표시됨 | 추정 면적을 확인된 측정값으로 오해할 수 있음 | UX-002 |
| 업로드·저장·자동 인식·편집·검토 기능이 동시에 노출됨 | 무엇부터 해야 하는지 알기 어려움 | UX-003 |
| 첫 시점에서 입체 벽이 원본과 바닥 일부를 가림 | 원본과 인식 결과를 비교하기 어려움 | UX-004 |
| `내 학원 조건 입력하기`를 누르면 입력칸보다 다수의 `추가 확인` 결과가 먼저 보임 | 입력을 시작할 위치를 찾기 어려움 | UX-005 |
| 치수 읽기 실패 시 `오늘 질문 한도` 안내만 표시됨 | 도면 작업과 오류의 관계, 복구 방법을 알기 어려움 | UX-006 |

위 현상은 화면 관찰 결과이며 실제 초보자 대상 사용성 시험 결과는 아니다. 자동 치수 읽기는 비회원 일일 한도에 막혀 성공 이후 흐름을 확인하지 못했다. 모바일 화면은 직접 검증하지 않았으며, 아래 모바일 항목은 구현 후 확인할 조건이다.

## 작업 범위와 기본 원칙

- 기존 도면 추출·편집·되돌리기·저장 기능과 디자인 토큰을 활용한다. 새 UI 프레임워크나 별도 편집 엔진은 도입하지 않는다.
- 이번 작업은 사용 순서, 표시, 조작과 복구 흐름을 개선한다. 벽 검출 알고리즘 교체, CAD 지원, 다층 편집은 포함하지 않는다.
- **도면 인식 검토**는 벽·문·구역 등 인식 결과를 확인하는 기능이다. **소방시설 검토**는 영업장 조건과 판단 규칙을 사용하는 기능이다. 두 기능의 이름·상태·결과를 구분한다.
- 법령 질문만 하는 사용자에게 도면 업로드나 영업장 입력을 강제하지 않는다. 도면 없이 영업장 조건을 직접 입력하는 경로도 유지한다.
- 단계 안내를 위해 기존 정보를 중복 저장하지 않는다. 단계별 화면을 다시 방문하거나 패널을 닫아도 현재 작업이 보존되어야 한다.

## 권장 작업 순서

P0는 먼저 수정할 혼란과 표시 문제, P1은 이어서 개선할 사용 흐름이다. 각 작업은 아래 완료 조건을 만족하는 단위로 나누어 PR을 만든다.

| 순서 | 작업 | 우선순위 | 선행 작업 | 결과물 |
|---|---|---|---|---|
| 1 | UX-001 · 툴바와 도면 작업 영역 안정화 | P0 | 없음 | 좁은 패널에서도 읽히고 움직이지 않는 작업 화면 |
| 2 | UX-002 · 축척 출처와 면적 상태 표시 | P0 | 없음 | 추정·자동 인식·사용자 확인을 구분하는 수치 표시 |
| 3 | UX-006 · 실패·한도·저장 상태의 복구 동선 | P0 | UX-002의 수동 길이 설정 진입점 | 오류 뒤에도 작업을 이어가는 화면 |
| 4 | UX-003 · 단계별 안내와 쉬운 용어 | P1 | UX-001, UX-002, UX-006 | 현재 상태에 맞는 다음 행동 안내 |
| 5 | UX-004 · 평면 중심 확인과 안전한 편집 | P1 | UX-001 | 원본 비교, 편집 종료, 되돌리기가 분명한 뷰어 |
| 6 | UX-005 · 영업장 입력 후 결과 확인 | P1 | 없음; 도면 연결은 UX-002, UX-003 연동 | 필요한 정보부터 입력하는 검토 흐름 |
| 7 | UX-007 · 회귀 및 초보자 사용성 검증 | P1 | UX-001~UX-006 | 실행 가능한 검증과 사용성 관찰 기록 |

첫 반영 범위는 UX-001·UX-002·UX-006으로 한다. 전면 개편 전에 가독성, 수치의 의미, 실패 후 다음 행동을 먼저 해결한다.

### 구현 기록 · 2026-09-19

- UX-001: 도구 버튼을 묶어 줄바꿈하고, 모드별 안내·입력 영역을 고정 높이 컨테이너로 옮겨 캔버스 크기를 유지했다.
- UX-002: 축척 상태(`assumed` / `estimated` / `auto` / `confirmed`)를 저장하고 면적·구역 면적에 추정 상태와 다음 행동을 표시했다. 마이그레이션 적용은 배포 절차에서 수행한다.
- UX-003~006: 도면 출처·진행 단계, 평면 기본 보기·편집 종료, 영업장 입력 우선 배치, 치수 읽기·저장 실패의 복구 행동을 반영했다.
- UX-007: 프런트엔드·서버 타입 검사와 테스트, Aside 브라우저의 좁은 패널·도면·영업장 입력 흐름을 확인했다. 실제 초보자 3명 과제와 운영 API 성공 경로 검증은 아직 수행하지 않았다.

## UX-001 · 툴바 줄바꿈과 편집 모드 전환 시 화면 이동 개선

- 우선순위: P0 · 유형: UI 수정
- 관련 기존 이슈: ISS-016
- 구현 시 확인할 위치: `frontend/src/components/planView.ts`, `frontend/src/styles/components.css`, `frontend/src/styles/layout.css`

### 문제

작업 버튼과 긴 상태 메시지가 한 줄의 폭을 나눠 가져 버튼 글자가 세로로 갈라진다. 편집 설정이 캔버스 위에 추가되면서 도면 영역도 줄어든다.

### 작업

1. 파일 작업, 편집 도구, 보기 도구를 각각 묶고 상태·오류 안내를 별도 영역에 둔다.
2. 버튼 문구 안의 줄바꿈을 막고, 공간이 부족하면 버튼 묶음이나 버튼 전체가 다음 줄로 이동하게 한다.
3. 도면 영역과 설정 영역을 분리한다. 같은 화면 크기에서 모드 전환만으로 캔버스 위치·크기가 바뀌지 않게 하고, 설정이 길면 설정 영역에서 스크롤한다.

### 완료 조건

- [ ] 검토 패널 폭 360px·440px·760px에서 버튼 글자가 한 글자씩 갈라지거나 서로 겹치지 않는다.
- [ ] 정상·처리 중·긴 오류 메시지가 나와도 버튼이 화면 밖으로 밀려나지 않는다.
- [ ] 동일한 화면·패널 크기에서 보기·벽 추가·문 추가·실제 길이 설정을 전환해도 캔버스 위치와 크기가 유지된다.
- [ ] 키보드로 도구와 설정에 접근할 수 있고 현재 포커스가 보인다.

## UX-002 · 축척의 출처와 확인 상태를 면적 옆에 표시

- 우선순위: P0 · 유형: 상태 표시·입력 개선
- 구현 시 확인할 위치: `frontend/src/components/planView.ts`, `frontend/src/api/plans.ts`
- 구현 참고: [도면 기능 구현 안내 §6.3, §8.8~8.9](plan-3d-guide.md)

### 문제

벽 두께 가정으로 계산한 면적이 실제 치수에 기반한 값처럼 보인다. 자동으로 값을 얻었다는 사실과 사용자가 그 값을 확인했다는 사실도 구분할 필요가 있다.

### 작업

1. 기존 축척 데이터의 출처를 활용해 면적 옆에 다음 상태를 표시한다. 내부 계산용 정밀도와 사용자에게 보여주는 확실성은 분리한다.

   | 값의 출처·상태 | 표시 예시 | 다음 행동 |
   |---|---|---|
   | 벽 두께 가정 | `임시 추정 · 실제 길이 미설정` | 실제 길이 맞추기 |
   | 표준 물체 치수로 어림 | `추정 · 표준 치수 기준` | 실제 길이 맞추기 |
   | 도면의 치수를 자동으로 읽음 | `자동 인식 · 확인 필요` | 읽은 구간과 길이 확인 |
   | 읽은 치수를 사용자가 확인하거나 직접 길이를 입력함 | `사용자 확인 · 입력 치수 기준` | 기준 길이 수정 |

2. 수동 설정은 `시작점·끝점 선택 → 실제 길이와 단위 입력 → 적용`으로 안내한다. 자동 인식은 읽은 구간과 값을 보여준 뒤 확인·수정하게 한다.
3. 추정값에는 `약`과 상태 문구를 함께 표시한다. 사용자 확인 후에도 인식된 벽과 구역에 따른 계산값임을 유지하고, 실측·공식 면적이 검증되었다고 표현하지 않는다.
4. 도면 교체 시 이전 도면의 확인 상태를 해제한다. 저장본에는 확인 근거가 있을 때만 해당 상태를 복원하며, 근거가 없는 기존 데이터는 확인을 요청한다.

### 완료 조건

- [ ] 전체 면적과 구역별 면적을 볼 때 같은 화면에서 축척의 출처와 확인 여부를 알 수 있다.
- [ ] 자동 인식 실패·취소 시 기존 도면과 유효한 사용자 입력값을 유지하며, 확인 상태를 성공으로 바꾸지 않는다.
- [ ] 길이가 0·음수·숫자가 아니거나 기준 구간의 길이가 0이면 적용하지 않고 입력 위치에 수정 안내를 표시한다.
- [ ] 도면 교체 후 늦게 도착한 응답이 새 도면의 수치와 확인 상태를 덮어쓰지 않는다.
- [ ] 추정 면적이 영업장 조건의 확인된 값으로 자동 반영되지 않는다. 값을 가져오는 경우 출처를 보여주고 별도 확인을 받는다.

## UX-003 · 도면 준비부터 검토까지 다음 행동 안내

- 우선순위: P1 · 유형: 사용 흐름 개선
- 선행: UX-001, UX-002, UX-006
- 구현 시 확인할 위치: `frontend/src/components/planView.ts`, `frontend/src/components/panel.ts`

### 문제

여러 기능이 같은 비중으로 보이고, 열린 도면이 예시인지 내 파일인지 판단하기 어렵다. 전문 용어도 작업의 목적을 바로 전달하지 못한다.

### 작업

1. 상단에 `도면 준비 → 실제 길이 확인 → 인식 결과 확인 → 소방시설 검토`의 진행 상태를 표시한다. 별도 마법사 프레임워크 없이 기존 화면과 액션을 연결한다.
2. 도면 준비에서 `내 도면 올리기`와 `예시 도면으로 체험하기`를 구분하고 파일명·예시 여부를 계속 표시한다.
3. 현재 필요한 주 행동 하나를 강조한다. 길이를 모르면 `나중에 확인`으로 도면 확인·편집을 계속할 수 있지만 추정 상태는 남긴다. 실제 길이나 형상을 바꾸면 영향을 받는 확인·검토 결과를 갱신하거나 다시 확인하도록 표시한다.
4. 인식 결과 확인 단계에 `벽과 문이 실제 도면과 같은가요?`와 `맞아요`·`수정하기`를 둔다. 도면 AI 검토는 이 단계의 보조 기능으로 위치시키고, 소방시설 검토는 영업장 입력으로 연결한다.
5. 벽 높이·픽셀 기반 벽 인식 기준은 `인식 결과 조정`에 접어 두고, 필요한 사용자는 계속 조절할 수 있게 한다.

### 공통 문구

| 현재 | 변경 문구 |
|---|---|
| 축척 | 실제 길이 맞추기 |
| 치수 읽기 | 도면의 치수 자동 읽기 |
| 보기 | 도면 둘러보기 |
| 기본 도면 | 예시 도면 |
| 전체 보기 | 도면 전체 맞추기 |
| AI 검토 | 도면 인식 검토 |
| 벽 두께 기준 | 벽 인식 기준 — 고급 설정에서 px 단위와 설명 표시 |

### 완료 조건

- [ ] 처음 들어온 사용자도 현재 도면의 출처, 현재 단계, 다음 행동을 화면에서 확인할 수 있다.
- [ ] 이전 단계로 돌아가거나 패널·탭을 전환해도 도면과 편집 내용을 잃지 않는다.
- [ ] 길이나 벽을 변경한 뒤 이전 확인·검토 결과가 현재 도면의 결과인 것처럼 남지 않는다.
- [ ] 예시를 열거나 단계·탭만 전환하는 동작이 추가 AI 요청을 발생시키지 않는다.
- [ ] 기존 자동 치수 읽기·도면 검토가 있다면 단계 이동으로 중복 실행하지 않고 그 처리 상태를 표시한다.
- [ ] 일반 법령 질문과 도면 없는 영업장 검토 경로가 계속 동작한다.

## UX-004 · 평면 중심의 확인 화면과 편집 복구 제공

- 우선순위: P1 · 유형: 뷰어·편집 개선
- 선행: UX-001
- 구현 시 확인할 위치: `frontend/src/plan/viewer.ts`, `frontend/src/components/planView.ts`, `frontend/src/components/panel.ts`

### 문제

입체 벽이 바닥과 원본을 가리고, 둘러보기와 그리기가 같은 도면 영역을 사용한다. 작업 공간을 넓히는 기능과 도면을 화면 안에 맞추는 기능도 구분해야 한다.

### 작업

1. 기본 시점은 위에서 보는 평면으로 두고 `평면 보기 / 3D 보기`를 명시한다. 기존 뷰어의 카메라와 벽 표시를 조정해 평면에서 벽 높이가 원본·치수·구역을 가리지 않게 한다.
2. 원본 표시를 바로 켜고 끌 수 있게 하고, 구역 목록에서 선택하면 해당 도면 구역을 강조한다. 색상 외에도 구역 번호·이름으로 연결한다.
3. 벽·문 편집에 들어가면 현재 모드와 조작 방법을 표시한다. `편집 끝내기`, Esc 종료, `되돌리기`를 제공하고 보기 모드의 이동·회전과 그리기가 동시에 실행되지 않게 한다.
4. `도면 크게 보기`로 작업 공간을 넓히고 `이전 화면으로`로 복귀하게 한다. `도면 전체 맞추기`는 카메라 맞춤 기능으로 구분한다.

### 완료 조건

- [ ] 최초 도면이 평면으로 열리고 3D 왕복 시 편집 데이터·축척·구역 정보가 바뀌지 않는다.
- [ ] 구역 선택을 색만으로 표시하지 않으며 목록과 도면에서 같은 번호·이름을 확인할 수 있다.
- [ ] 편집 모드의 선택 상태가 시각적으로 보이고 접근성 속성으로도 전달된다.
- [ ] 진행 중인 그리기를 취소하면 미완료 변경이 남지 않고, 완료된 벽·문 편집은 되돌릴 수 있다.
- [ ] 화면 확대·복귀 시 기존 대화와 패널 상태가 복원되고 도면 작업이 보존된다.

## UX-005 · 영업장 조건 입력을 결과보다 먼저 제공

- 우선순위: P1 · 유형: 입력·결과 흐름 개선
- 관련 기존 이슈: ISS-020, ISS-034
- 구현 시 확인할 위치: `frontend/src/components/caseCard.ts`, `frontend/src/components/panel.ts`

### 문제

조건을 입력하려고 들어갔는데 여러 설비의 판단 불가 결과를 먼저 읽게 된다. 여러 건물·영업장 용어와 질문이 동시에 나와 처음 입력하는 부담도 크다.

### 작업

1. `내 학원 조건 입력하기`를 누르면 기본 입력 영역이 먼저 보이고 첫 입력으로 포커스를 이동한다. 정보가 부족할 때는 반복적인 설비별 경고 대신 필요한 입력을 요약한다.
2. 기본 정보부터 보여주고 기존 판단 규칙이 요구하는 추가 항목을 이어서 묻는다. 이미 확인된 값은 다시 묻지 않으며 `모름`을 유효한 응답으로 유지한다.
3. 질문은 일상 언어로 쓰고 전문 명칭은 설명으로 보조한다. 예: `영업장 층이 피난층인가` → `이 층에서 계단 없이 건물 밖 지상으로 나갈 수 있나요?`.
4. 결과는 `확인한 조건 → 시설별 결과 → 더 필요한 정보 → 근거 법령` 순으로 제공한다. 추가 정보 요청에서 해당 입력칸으로 바로 이동하게 한다.
5. 도면에서 면적을 가져올 때는 전체 바닥면적·구역 면적과 영업장 면적을 구분하고 사용자가 적용 대상을 확인하게 한다. 건물 연면적 등 다른 의미의 필드로 임의 복사하지 않는다.

### 완료 조건

- [ ] 입력 진입 직후 결과 목록을 스크롤하지 않아도 첫 질문에 답할 수 있다.
- [ ] 기본 정보 수정 후 실제로 필요한 추가 질문과 결과가 갱신되고, 숨겨진 이전 답변을 현재 조건에 부적절하게 적용하지 않는다.
- [ ] `모름`을 `아니오` 또는 `0`으로 취급하지 않으며 미확인 조건으로 남긴다.
- [ ] 도면 면적을 가져올 때 값·출처·추정 여부·적용할 면적 범위를 확인할 수 있다.
- [ ] 기존 규칙 결과와 근거 연결을 보존하고, 개발용·미승인 결과를 승인된 판단으로 표현하지 않는다.

## UX-006 · 치수 읽기·검토·저장 실패 후 다음 행동 제공

- 우선순위: P0 · 유형: 오류·상태 안내 개선
- 선행: UX-002의 수동 길이 설정 진입점
- 관련 기존 이슈: ISS-026
- 구현 시 확인할 위치: `frontend/src/components/planView.ts`, `frontend/src/api/plans.ts`

### 문제

치수 읽기에서 발생한 한도 오류가 `오늘 질문 한도`로 표시된다. 안내 근처에 실행할 복구 행동이 없고, 저장 버튼도 대상과 진행 상태를 더 분명하게 전달할 필요가 있다.

### 작업

1. 기존 오류 분류에 따라 작업 이름·원인·다음 행동을 같은 위치에 표시한다. 서버 오류 종류를 알 수 없을 때 한도나 로그인 문제로 임의 단정하지 않는다.
2. 한도 초과에는 `직접 길이 입력`을 제공하고, 계정 상태와 실제 정책상 도움이 될 때 `로그인`을 제공한다. 로그인만으로 모든 한도가 해제된다고 안내하지 않는다.
3. 일시적인 실패에는 `다시 시도`, 치수 인식 불가에는 `직접 길이 입력`을 제공한다. 자동 무한 재시도는 하지 않는다.
4. 저장 대상과 현재 상태를 실제 동작에 맞게 표시한다. 비회원 저장 지원은 유지하고, 서버 성공 전에는 저장 완료로 표시하지 않는다. 다운로드 기능이 아닌 저장을 다운로드로 이름 붙이지 않는다.

### 완료 조건

- [ ] 치수 읽기 한도 오류에 `자동 치수 읽기 이용 한도에 도달했습니다`와 실행 가능한 대안이 함께 보인다.
- [ ] 비회원/로그인 상태의 한도, 네트워크 실패, 인식 결과 없음에 맞는 복구 행동을 제공한다.
- [ ] 요청 중 같은 버튼을 반복해 눌러도 중복 요청이 발생하지 않는다.
- [ ] 실패·재시도·로그인 모달 취소로 원본·편집·사용자 입력 치수가 사라지지 않는다.
- [ ] 저장 중·저장 완료·저장 실패를 구분하고 실패 시 다시 저장할 수 있다.
- [ ] 상태 변경은 화면 낭독기로 전달되며 오류가 작업 포커스를 불필요하게 빼앗지 않는다.

## UX-007 · 회귀 검증과 초보자 사용성 확인

- 우선순위: P1 · 유형: 검증
- 선행: UX-001~UX-006
- 관련 기존 이슈: ISS-028
- 구현 시 확인할 위치: `e2e/aside/`, `e2e/package.json`, `frontend/src/plan/*.test.ts`

### 작업

기존 단위 시험과 Aside 브라우저 검증을 재사용한다. 새 상태 분기와 데이터 보존에 필요한 작은 회귀 검증을 추가하고, 레이아웃은 화면 캡처로 확인한다. 유료 AI를 반복 호출하지 않도록 오류·지연·성공 상태를 재현할 응답을 준비하고, 실제 연동 성공 경로는 한도가 허용될 때 별도로 확인한다.

| 검증 상황 | 확인할 결과 |
|---|---|
| 1440×900, 1280×800 및 검토 패널 폭 360·440·760px | 문구 잘림·겹침이 없고 모드 전환 시 도면 영역이 움직이지 않음 |
| 390×844 화면 | 주요 작업과 입력·오류 안내에 접근 가능하고 페이지 전체에 가로 스크롤이 생기지 않음 |
| 예시 / 업로드 / 저장본 | 출처가 표시되고 단순 진입·보기 전환으로 AI 요청이 중복되지 않음 |
| 가정 / 표준 치수 어림 / 자동 인식 / 사용자 확인 | 면적 옆 상태와 다음 행동이 실제 출처·확인 여부와 일치함 |
| 도면 A 처리 중 B로 교체 | A의 늦은 응답이 B의 결과·확인 상태를 덮어쓰지 않음 |
| 벽 추가·문 추가 → 종료·취소·되돌리기 | 미완료 작업과 완료 작업이 구분되어 복구됨 |
| 한도·네트워크 실패·저장 실패 | 작업 데이터가 유지되고 수동 입력 또는 재시도가 가능함 |
| 영업장 정보 입력·수정·모름 | 필요한 질문과 결과가 갱신되며 미확인이 임의 확정으로 바뀌지 않음 |

처음 사용하는 사람 3명에게 다음 과제를 설명 없이 제공한다. 인원과 기준은 이번 개선을 확인하기 위한 초기 사용성 검증 목표다.

1. 예시 도면을 열고 지금 면적이 어떤 기준으로 계산됐는지 설명한다.
2. 제공한 길이 정보를 이용해 실제 길이를 맞추고 설정 결과를 확인한다.
3. 벽 하나를 수정한 뒤 되돌리고, 영업장 정보 입력으로 이동한다.

### 완료 조건

- [ ] 변경 범위의 타입 검사·빌드와 관련 기존 시험을 통과하고, 추가한 상태 전이·복구 검증을 다시 실행할 수 있다.
- [ ] 위 표의 결과와 화면 캡처를 PR에 기록한다. 실제 AI 성공 경로를 못 확인한 경우 재현 응답 검증과 구별해 미검증으로 남긴다.
- [ ] 3명의 과제 완료 여부·도움 요청 지점·잘못 이해한 문구를 기록한다. 테스트 전에는 완료로 표시하지 않는다.
- [ ] 작업을 진행하지 못하거나 추정값을 확인된 값으로 오해한 문제는 수정 후 해당 과제를 다시 확인한다.
- [ ] [사용자 안내](user-guide.md)에 바뀐 문구와 흐름을 반영하고, 단계별 안내·축척 확인 동작이 달라진 부분은 [구현 안내](plan-3d-guide.md)에도 반영한다.
