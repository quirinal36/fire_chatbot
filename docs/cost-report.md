# 호출량·비용·성능 측정 보고서 (ISS-027)

측정일 2026-09-18 · 측정 결과 원본 [`evals/load/load-1789664218912.json`](../evals/load/load-1789664218912.json) · 재실행 `node scripts/load-test.mjs`

대상 독자: 운영비를 정하는 의뢰자와 소방 업무 담당자, 운영을 넘겨받는 개발자.

## 요약

- 질문 1건의 모델·임베딩 비용은 **평균 $0.0073, p95 $0.0133**이다 (`anthropic/claude-haiku-4.5`).
- 월 10,000건이면 모델비가 **약 $73~95**다. 클라우드 요금제(Vercel Pro $20 + Supabase Pro $25)를 더하면 **월 약 $120~140**이다.
- 최종 답변 지연 p95는 **12.4초**로 목표(20초) 안이다. DB가 뭄바이 리전에 있어서 생기는 지연이 포함된 값이다.
- 인용한 근거 190건 중 조회되지 않는 근거는 **0건**이었다.

| 측정 위치 | 개발 PC(서울) → 운영 API |

## 월 비용 환산

**모델·임베딩**

질문당 평균 $0.0073(재요청 포함)을 기준으로 잡았다. 대화가 길어져도 이전 대화를 모델에 넣지 않으므로 문맥 누적 비용은 없다. 한 번에 질문 하나만 처리한다.

| 월 질문 수 | 평균 기준 | 보수적 (p95 30% 가정) |
|---:|---:|---:|
| 1,000 | $7.3 | $9.1 |
| 10,000 | $73 | $91 |
| 50,000 | $366 | $456 |

보수적 값은 질문의 30%가 p95 비용($0.0133)이 든다고 가정한 것이다: 0.7 × 0.0073 + 0.3 × 0.0133.

문서 임베딩은 개정이 있을 때만 바뀐 조각을 다시 계산한다. 전체 재임베딩도 약 $0.03이라 월 비용에 영향이 없다.

**클라우드** (요금 확인일 2026-09-18, 공식 요금 페이지 기준)

| 서비스 | 지금 | 운영 권장 | 근거 |
|---|---|---|---|
| Vercel | Hobby $0 | **Pro $20/월**(개발자 1석) | Hobby는 비상업용으로 제한된다. Pro에는 함수 호출 100만 건/월, Active CPU 4시간/월, 전송량 1TB/월이 포함된다 |
| Supabase | Free $0 | **Pro $25/월** | Free는 1주일간 사용이 없으면 일시 정지된다. DB 용량 한도는 500MB로, 현재 사용량은 181MB다. Pro에는 디스크 8GB, 파일 저장 100GB, 전송량 250GB, 컴퓨트 크레딧 $10이 포함된다 |
| OpenRouter / OpenAI | 사용량 과금 | 선불 충전 | 위 모델비 |

월 50,000건이라도 Vercel 함수 호출은 요청당 1~2회라 포함량(100만 건) 안이다. Active CPU는 요청이 대부분 모델 응답을 기다리는 시간이라 크게 늘지 않을 것으로 보지만, **Pro 전환 후 1주일간 실측해 확인해야 한다.**

## 비용 상한과 경보

| 설정 | 현재 값 | 위치 |
|---|---|---|
| 일일 모델·임베딩 비용 상한 | $5 (넘으면 새 질문 거부) | `DAILY_BUDGET_USD` |
| 비회원 하루 질문 수 | 30 | `LIMIT_ANON_PER_DAY` |
| 로그인 사용자 하루 질문 수 | 100 | `LIMIT_USER_PER_DAY` |
| IP별 하루 질문 수 | 200 | `LIMIT_IP_PER_DAY` |
| 질문 길이 | 1,000자 | `MAX_QUESTION_CHARS` |
| 모델 출력 상한 | 1,500 토큰, 모델당 최대 2회 | `openrouter.ts`, `answer.ts` |

$5/일은 월 약 $150이다. 월 10,000건(하루 약 330건, $2.4/일)은 충분히 감당하지만, 하루 700건을 넘으면 상한에 걸린다. **운영 규모가 정해지면 담당자와 다시 정한다** (ISS-029).

관리자 화면의 운영 지표에 경보가 뜨는 기준:

- 오늘 비용이 상한의 80%를 넘었을 때
- 실패·대체 응답이 5%를 넘었을 때
- 근거 부족이 40%를 넘었을 때 (질문 20건 이상)
- 응답 지연 p95가 20초를 넘었을 때
- 실패한 수집 작업이 있을 때

화면에 표시하는 경보라서 알림을 보내지는 않는다. 메일 등 외부 알림은 운영 연락 체계가 정해진 뒤에 붙인다 (ISS-029).

## 성능 개선 여지

- **DB 리전**: 뭄바이 DB와 서울 함수 사이의 왕복 지연(RPC 1회에 약 170ms)이 질문 1건에 6~8회 생긴다. 서울 리전 프로젝트로 옮기면 약 1초가 줄어든다. 사용자가 리전을 옮길 예정이다.
- **모델 지연**: 모델 응답이 전체 지연의 대부분(4~8초)을 차지한다. 근거 본문을 줄이면 입력 토큰과 지연이 함께 준다.
